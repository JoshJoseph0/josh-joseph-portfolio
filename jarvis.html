The starting point

I wanted to explore a desktop assistant I would actually use: somewhere for calendar information, weather, news, notes and stock data, with typed and spoken input.

The interface is only one part

The interesting work sits between the interface and the services behind it. I’ve been working through speech-to-text, text-to-speech, API configuration and how application state changes when a request comes back.

Following the whole problem

When something fails, I try to trace the route from input to response. That means looking at the audio, the API request, the state and the visible feedback together, rather than treating each screen as a separate problem.

Where it stands

The prototype is in development. My next focus is making requests more reliable and giving clear feedback when a service is slow or unavailable.
